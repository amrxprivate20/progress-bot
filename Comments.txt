# Progress Bot - Issues to Address

## High Priority Fixes

### 1. Todoist Pre-Sync for /today and /progress
**Issue:** The /today and /progress commands currently rely only on task completion sync. They need to perform a pre-sync with Todoist first before displaying information.

**Required Implementation:**
- Add a Todoist sync call at the beginning of both /today and /progress commands
- Ensure fresh data is retrieved before any display or analysis
- Handle sync errors gracefully with user notification

### 2. Previous Day Report Handling in /progress
**Issue:** If the time passes midnight and the user hasn't done the analysis, that day's data won't be saved to the database.

**Required Implementation:**
- Always check if the previous day's data is saved to the database when /progress is called
- If unsaved data exists, prompt the user: "Yesterday's report was not saved. Would you like to:
  1. View and save yesterday's report first
  2. Skip yesterday and proceed with today's report"
- Save the appropriate day's data based on user selection

### 3. /sync Manual Sync Not Working
**Issue:** The manual sync command does nothing.

**Required Implementation:**
- Debug the /sync command
- Ensure it properly triggers Todoist synchronization
- Provide user feedback during sync (loading indicator)
- Confirm successful sync or show error message

### 4. /starttask - Multiple Matching Tasks
**Issue:** When searching for a task, it returns only the first similar match instead of showing all possible matches.

**Required Implementation:**
- Modify search logic to find ALL matching tasks
- If multiple matches found, display numbered list: "Multiple tasks found:
  1. [Task Name 1]
  2. [Task Name 2]
  3. [Task Name 3]
  Please enter the number of the task you want to start:"
- Accept user input for selection
- Only if one match found, start it directly

### 5. Session Midnight Boundary Handling
**Issue:** Sessions that start before midnight and end after midnight are being saved to the wrong day.

**Required Implementation:**
- Track session start time separately
- For any session (interactive conversation, task timer, journaling, etc.):
  - Record the start date/time
  - Save the session to the day it STARTED, not the day it ended
- Applies to: task timers, journaling sessions, interactive conversations, and any other time-tracked activities

### 6. Remove /quran Command
**Issue:** Need to remove the /quran command and its associated feature.

**Required Implementation:**
- Remove /quran command handler
- Remove any related database tables/fields
- Remove any UI elements or menu items
- Clean up any references in codebase

## New Features to Implement

### 7. Tomorrow Planning Question
**Required Implementation:**
- Add a permanent daily question asking: "Is tomorrow a workday, holiday, or does anything special need to be noted for tomorrow's task planning?"
- Store this information for use in planning algorithms
- Make it part of the daily routine/check-in

### 8. Tomorrow's Suggested Plan Command
**Required Implementation:**
- Create new command (suggest name: /plan or /tomorrow)
- Command should generate:
  - Suggested schedule for tomorrow with time slots
  - Estimate duration for each task
  - Categorize what can be done during work vs. personal time
  - Consider: workday/holiday status, task priorities, deadlines, energy levels
- Format as actionable daily schedule

### 9. Widget Data API Endpoints
**Issue:** Need to replicate Google Sheets widget functionality with custom links.

**Required Implementation:**
Create endpoints that return plain text data for widgets:
- `/api/widget/last-reward` - Returns the last reward earned
- `/api/widget/today-report` - Returns current day report (similar to /today output)
- `/api/widget/daily-challenge` - Returns today's challenge
- `/api/widget/weekly-challenges` - Returns this week's challenges with results

Each endpoint should:
- Be accessible via simple GET request
- Return plain text format suitable for widget display
- Include authentication if necessary
- Cache appropriately for performance

### 10. Enhanced /goals Command
**Required Implementation:**
- Expand /goals to show:
  - Today's daily challenge (existing)
  - Full list of this week's daily challenges
  - Status/result for each challenge (completed, failed, pending)
  - Weekly progress summary

## Bug Fixes

### 11. Task Creation Day Assignment
**Issue:** Some tasks after creation are assigned to random days because day ranges aren't clear.

**Required Implementation:**
- Before sending task creation prompt, determine and explicitly list available days
- Include available day ranges in the prompt
- Ensure AI has clear context about valid day assignments
- Validate day assignment before saving task
- If invalid, re-prompt or default to sensible fallback

### 12. Supabase Storage Upload Error
**Issue:** Image uploads failing with error: "Invalid Compact JWS" (403 Unauthorized)

**Error Log:**
```
📤 Supabase response: 400 {"statusCode":"403","error":"Unauthorized","message":"Invalid Compact JWS"}
Storage upload failed: Bad request - check bucket configuration
```

**Required Implementation:**
- Fix JWT token generation/validation for Supabase
- Verify Supabase service key is correctly configured
- Check bucket permissions and policies
- Ensure proper authentication headers are sent
- Test with: bucket 'journal-media', path format 'journal/2026-01-18/image_[timestamp].jpg'
- Add better error handling and logging for storage operations
